# 任务 XFZCLEAN：小饭桌生产库测试走查数据清理（所有者已授权）

一句话任务：清空 https://xiaofanzhuo.asterforge.top 生产库里 Agent D 遗留的测试数据（7 道测试菜品 + 8 张测试订单），备份留档后执行，并验证线上回到干净空态。

## 背景（已核实事实，勿重新考古）

- 小饭桌：Next.js 16 + Prisma + SQLite（standalone），腾讯云单机 Ubuntu + nginx + systemd。仓库 `xiaofanzhuo/`（你的 cwd，工作树干净）；部署细节以仓内 `README.md` 与 `docs/DEPLOY.md` 为唯一权威（生产 DB 文件路径、服务名以那里为准）。
- wave6 INSPXZ 巡检（已验收）实证生产现状：午餐 4 菜（红烧肉 ¥28「微辣 · 2 人份」、番茄炒蛋 ¥15、紫菜蛋花汤 ¥8、白米饭 ¥2）+ 晚餐 3 菜（可乐鸡翅 ¥26、清炒时蔬 ¥12、小米粥 ¥5），共 7 道，全部为 Agent D 测试走查残留；历史审计口径另有 8 张测试订单。
- **所有者（用户）已明确授权本次清理**：7 道测试菜 + 8 张测试单清零，站点回空盘状态，商家之后会在 `/admin` 重新上架真实菜单。

## 步骤

1. 读仓内 `README.md` / `docs/DEPLOY.md`（及 Prisma schema `prisma/schema.prisma`），确定：生产 DB 文件在服务器上的绝对路径、表/模型名（菜品、订单、以及订单与菜品的关联表）、systemd 服务名。
2. SSH 连通性预检。**不通则如实报 failed 收档**（本机代理 TUN 近期抖动）。
3. **清理前盘点（只读 SELECT，结果全部留档进报告）**：
   - 菜品总数与逐条明细（名称/价格/分类）；
   - 订单总数与逐条关键信息（下单时间、总金额、收货人）。
4. **安全闸门**：若盘点结果与「7 菜 + 8 单」的测试残留口径不符——特别是出现**疑似真实订单**（收货人为真实姓名/手机号、时间在走查窗口之后的近期订单）——**立即中止，不动任何数据，如实报 failed** 并在报告写明发现了什么。宁可空跑不可误删。
5. 备份：在服务器上 `cp` 生产 DB 文件为带时间戳的备份（如 `prod-<date>.bak.db`），备份路径写进报告；确认备份文件非零大小。
6. 执行清理：用 sqlite3 在**单事务**内删除——8 张测试订单（先删订单-菜品关联行，再删订单行）、7 道测试菜品；**不动**设备/配置/其他任何表。提交后立即 `SELECT count(*)` 复核两表为 0。
7. 若菜单页有 ISR/缓存导致线上仍显示旧菜：按仓内 DEPLOY 文档的方式让缓存失效（如 systemd 重启小饭桌服务前先 `pgrep` 确认无并行维护在跑——同一台服务器上另有部署/nginx 任务在进行，错开它们的时机）。
8. **线上验证（证据留报告）**：`https://xiaofanzhuo.asterforge.top/` 200 且菜品为空态（无 7 道测试菜）；`/checkout` `/orders` `/me` 均 200；无 5xx。
9. 整文件覆盖写报告。

## 红线

- 只删盘点中逐条确认过的测试行；**任何对不上预期的情况 → 中止 + 如实报告**，绝不带疑点删数据。
- 删前必有备份；备份失败 → 中止。
- 不改 schema、不跑 migration、不动小饭桌之外的任何服务/站点。
- 密钥零入报告零落盘；Windows 11 + PowerShell；失败如实报，不盲重试。
