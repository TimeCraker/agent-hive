# 任务 AUDLKS:lekao 代码安全审计(只读)

一句话任务:对 lekao(K12 机构 AI 助教工作台,线上 lekao.asterforge.top)的仓内代码做**只读**安全审计——API 鉴权覆盖、签到 T-Coin 防刷、注入与硬编码密钥、依赖漏洞——产出 P0-P3 分级清单。**不碰线上服务,不利用发现的漏洞做任何写操作验证。**

## 背景(已核实事实,勿重新考古)

- 技术栈:Next.js 16 + Prisma + next-auth + ioredis;免费模式(签到得 T-Coin,无付费充值);CI + husky。指引:`lekao/README.md` + CHANGELOG(先读)。
- 审计对象是**仓内代码**,不是线上接口;对线上的结论仅作为背景,不主动打线上。
- 同工作区另有并行波次在做各仓**文档保鲜审计**(只改 .md);`git status` 里的 .md 未提交改动是他们的,原样保留。

## 步骤

1. **API 鉴权覆盖矩阵**:枚举 `app/api/`(或实际路由目录)全部路由,逐条判定:公开 / 需登录 / 需特定角色;判定依据引用代码行(如 `getServerSession` 调用、middleware 拦截)。**矩阵表格是核心交付物**——"应有鉴权却公开"的路由 = P0。
2. **签到 T-Coin 防刷**:定位签到/发 T-Coin 的接口与逻辑,审查防重放(幂等键/每日限一次的实现)、防脚本刷(频控)、并发竞态(同秒双发)。免费模式的经济系统被刷穿 = P0/P1。
3. **注入与数据安全**:全仓搜 `$queryRaw`/`$executeRaw`/字符串拼接 SQL;Prisma 参数化之外的原生查询逐条审;next-auth 配置(callbacks/session)是否泄露敏感字段。
4. **硬编码密钥**:`git grep` 密钥形态(sk-/key=/token=/secret),命中记录路径+变量名+性质(真实/示例),**报告不抄值**。
5. **依赖漏洞**:`pnpm audit --prod`(只读 lockfile 与 registry 查询,允许;失败重试 ≤2,再失败标"未获取到")。**禁止 pnpm install。**
6. 汇总写报告。

## 红线

- **只读仓内 + 零线上写操作**:绝不调用任何线上写接口(签到/登录/发帖);发现漏洞只记录证据,不利用、不复现写操作。
- 除报告外零写入;无 git 写操作;不 install 依赖。
- Windows 11 + PowerShell;China 网络重试 ≤2。

## 验收标准

1. API 鉴权覆盖矩阵覆盖 100% 路由(数量留证:路由总数 × 已判定数);
2. 签到防刷有明确代码级结论(引用文件+行号);
3. 分级清单 P0-P3 每条附证据(路径:行号 / 命令输出)。
