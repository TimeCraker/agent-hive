## 步骤

1. **三态切换**：基础编辑 ↔ AI 编辑 ↔ 预览：切换不丢未保存输入、预览内容与编辑内容一致、切换回来光标/滚动位置合理；console 无新增错误。
2. **制作模式**：自由制作 与 引导制作（guided）各走一遍：**引导必须能返回**（返回不丢已填内容）；引导步骤前进/后退/跳过行为正常。
3. **结构操作逐项**（每项操作→断言→截图）：
   - 段落拖拽（dnd-kit）：拖动区块顺序，预览同步。
   - 条目排序：经历/技能条目上下移或拖拽，顺序持久（刷新后仍新顺序）。
   - 展开编辑：条目展开/收起，展开态字段完整。
   - 富文本（Tiptap）：加粗/列表/链接等基础操作，内容正确渲染进预览。
   - 增/删：新增经历/项目/技能条目、删除条目（有确认则验证确认行为）。
4. **自动保存**：编辑后不手动保存，等自动保存触发（观察 network 的 PATCH/PUT 或保存指示器），刷新页面内容仍在；记录自动保存触发时机/指示。
5. **撤销重做**（Zustand 50 步 undo/redo）：连续多步操作后 Ctrl+Z 逐步回退、Ctrl+Shift+Z/Ctrl+Y 重做，断言内容与指示一致；跨自动保存点的撤销行为记录（若撤销后自动保存又把内容存回去，记录实际语义）。
6. **侧栏缩放**：预览缩放控件 +/-/适配，缩放后排版不破、截图目检。
7. **建议语义**（handoff 第 4 项原文）：
   - 采纳/忽略可以撤回：忽略的建议有撤回入口，撤回后建议重新可见。
   - 已应用修改有撤回入口。
   - **未采纳建议不写入**：忽略建议后保存/刷新，内容不含该建议（network + 刷新断言）。
   - **冲突不覆盖新内容**：建议 pending 时手动改同一字段，建议应用/刷新后以新内容为准（构造一次冲突场景记录实际行为）。
   - 若建议产生依赖 AI 调用而渠道未就绪：用已有存档建议（若有）验证 UI 语义；无存档则登记未测原因，UI 入口存在性仍要验证。
8. **视口与键盘**：编辑器 390/1440 各一轮（390 必过：侧栏收纳、工具条可达、无横向溢出）；键盘 Tab 顺序、Escape 关弹层焦点恢复、Enter 在富文本内换行不误触发表单提交。
9. **缺陷处理**：编辑器属于 legacy 线「只修 Bug 不动」——简单缺陷（按钮不可达、文案、裁切溢出、间距、简单状态）可修：一个缺陷一个 commit（中英文 Conventional Commits）→ rebuild → 同条件前后截图回归；内容合并/撤回逻辑类（冲突覆盖、状态污染）**只取证交回**；独占文件（五个基础内容编辑表单、content-section-draft.ts 等，见 handoff 清单）只记不修。
10. **登记**：走查文档 EDIT 分区逐项结果 + 台账；测试简历保留。
