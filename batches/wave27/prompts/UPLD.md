## 步骤

1. **素材构建**（全部合成，含【E2E】标记，禁用任何真实简历）：
   - TXT：UTF-8 中文简历（全名、复姓「欧阳」、联系方式、多段经历、日期区间、技能、教育）。
   - 文字层 PDF：用可用的本机工具生成（如 headless Chrome 打印 HTML→PDF、或已装的办公工具导出）；至少两个变体：双栏+题头版、多页版；一个缺字段版（无邮箱/无教育）。
   - DOCX：本机有 python-docx/docx 工具链就生成；没有则登记「DOCX 生成工具不可用」证据后跳过并标注未测原因（不得伪造 docx）。
   - 扫描图片：把简历页渲染成 PNG（整页一张图）上传，或上传纯 PNG。
   - 每个文件内容刻意覆盖：中文全名/复姓、题头、双栏、长经历（≥6 段）、多页、缺字段。
2. **上传走查**（每个文件独立一轮）：
   - 经 dashboard → 创建/上传入口进入上传页；file chooser 流程上传（文件绝对路径）。
   - 观察队列状态轮询：记录提交→完成/失败的**实际耗时**与警告文案；browser_network_requests 过滤解析相关接口状态码。
   - 解析完成后进入**核对页**：对照原文件逐项检查姓名、邮箱/电话、日期、经历条数、技能、教育——逐字段记录 一致/丢失/错误；截图目检。
   - 期望断言：复姓「欧阳」完整；题头姓名不丢；双栏内容都抓到；多页不截断；缺字段不误造（无中生有的字段要记缺陷）。
3. **核对页交互**（handoff 第 3 项原文要求）：
   - 修改姓名/日期/成果；添加一条经历；保存 → 下一步 → 进编辑器 → **刷新页面** → 必须看到同一修改（持久化断言，必要时查只读 DB 核对）。
   - 无效邮箱：保存被拦、明确提示、停留本页、输入保留。
   - 断网保存：browser_set_offline（或等效）后点保存：失败提示明确、恢复网络后输入还在、可重新保存成功。
   - 重复点击保存：不产生重复记录/不误跳转（network 请求次数核对）。
   - **只打开核对页不得自动调用 AI**：打开核对页时 browser_network_requests 断言无 AI 调用（评分/润色等）发起。
   - 「去修改经历」定位展开、在职切换禁用/启用结束日期（前次已验证项，快速回归即可）。
4. **异常负例**：不支持格式（如 .exe/.zip）上传被拦有提示；空文件/超大文件行为；上传中离开页面提示。
5. **视口**：上传页与核对页 390/768/1440 至少各一轮完整截图目检（390 必过：无横向溢出、输入 ≥44px、邮箱/意向全宽——前次已验证项快速回归）。
6. **缺陷处理**：本任务范围大部分是独占文件——**一律只记台账（编号/根因猜测/证据）不修改**。可修的仅限：明确不属于独占文件的周边简单缺陷（如 dashboard 上传入口按钮、通用组件文案），修复→rebuild→回归→commit（中英文 Conventional Commits）。
7. **登记**：走查文档 UPLD 分区：每个文件的链路结果表（文件/耗时/字段核对明细/结论）+ 台账。测试简历保留（后续 EDIT/AIFLOW/LAYPDF 任务复用【E2E】素材）。
